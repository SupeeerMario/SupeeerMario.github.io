About me

I'm Khaled, a backend engineer from Alexandria, Egypt. I graduated in Software Industry & Multimedia from Alexandria University in 2024 and have spent my time since building the kind of systems that break in expensive ways: payments, bulk imports, monitoring.

My habit is simple. Before I call something done, I try to kill it. I fire concurrent requests at the same invoice, kill a worker mid-import, point a monitor at an endpoint that never answers. Then I write the test that fails when the guarantee breaks, so the fix stays fixed.

I work mostly in Python, Node.js and Go on PostgreSQL, MongoDB and Redis. Right now I'm going deeper on DevOps (CI, containers, deploying to real VMs) and picking up frontend so I can ship a feature end to end.

Bulk file import pipeline

node.js · mongodb · redis streams · minio

Failure: the worker dies halfway through a huge import.

500,000 / 500,000rows after killing the workerPASS
how it's guarded

guardEach 1,000-row chunk commits with its checkpoint in one MongoDB transaction, so a second worker resumes exactly where the first died. Redis Streams consumer groups, idempotent upserts, dead-letter stream after 5 attempts.

$ import 500,000 rows (30 MB)   memory: 120-131 MB flat
$ kill worker-1                  # mid-import
$ start worker-2                 # resumes from checkpoint
rows: 500,000   gaps: 0   duplicates: 0   PASS
